# Runtime Controller-Readiness Matrix

Plan: `process-unit-misalignment-two-pass`
Task: `3 - Map controller-readiness against runtime/subsystem contracts`

## Contract Baseline

- `ControlElement` binds the manipulated variable through `mv_tag`, resolves that tag from the process model or point registry, and writes controller output through the resolved setter (`src/modular_simulation/components/control_system/control_element.py:32`, `src/modular_simulation/components/control_system/control_element.py:64`, `src/modular_simulation/components/control_system/control_element.py:103`, `src/modular_simulation/components/control_system/control_element.py:148`).
- `AbstractController` requires a resolvable `cv_tag` point and a setpoint trajectory before it can wire to an element (`src/modular_simulation/components/control_system/abstract_controller.py:31`, `src/modular_simulation/components/control_system/abstract_controller.py:46`, `src/modular_simulation/components/control_system/abstract_controller.py:144`, `src/modular_simulation/components/control_system/abstract_controller.py:215`).
- Runtime activation rejects controllers that lack an input signal, lack an actuator binding, point at a non-measured/non-calculated CV, point at an unknown actuator, or mismatch CV/MV dimensionality (`src/modular_simulation/framework/system.py:780`, `src/modular_simulation/framework/system.py:789`, `src/modular_simulation/framework/system.py:798`, `src/modular_simulation/framework/system.py:805`, `src/modular_simulation/framework/system.py:907`).
- Native system validation still defines first-class actuator tags as `process_model.controlled_view.state_list`, so `T.CONSTANT` knobs are not first-class control elements even if a late-added wrapper can sometimes proxy them (`src/modular_simulation/framework/system.py:265`, `src/modular_simulation/framework/system.py:267`, `src/modular_simulation/measurables/process_model.py:482`, `src/modular_simulation/measurables/process_model.py:495`).
- Subsystems only accept local CV and MV tags; wrapped units satisfy this by publishing algebraic and differential outputs in the descriptor publication map and then refreshing the published view with the full process-model state list (`src/modular_simulation/connection/unit_process_wiring.py:27`, `src/modular_simulation/connection/unit_process_wiring.py:67`, `src/modular_simulation/connection/subsystem_descriptor.py:134`, `src/modular_simulation/connection/subsystem_descriptor.py:143`, `src/modular_simulation/connection/subsystem_descriptor.py:195`).
- The generic runtime path is proven by `tests/components/test_controller_wiring_api.py:133`, and subsystem-local CV/MV gating is proven by `tests/connection/test_subsystem_scoped_installers.py:38` and `tests/connection/test_subsystem_scoped_installers.py:86`.
- For this matrix, `controller-ready` means the unit already exposes a meaningful runtime actuator as a first-class `T.CONTROLLED` state; `ready-with-adapter` means the unit has a plausible actuator, but only as a `T.CONSTANT`, embedded setpoint, or internal control hook that needs a wrapper/published proxy; `not-ready` means the existing knobs are passive inputs, equipment-definition parameters, or discrete/model-definition settings that do not form a safe runtime actuator under the current contracts.

## Outcome

- `controller-ready`: `heater_cooler`, `flash_drum`, `valve`, `splitter`, `shortcut_distillation`
- `ready-with-adapter`: `cstr`, `pfr`, `pump`, `component_separator`
- `not-ready`: `conversion_reactor`, `heat_exchanger`, `mixer`

## Notes

- `heater_cooler` is the strongest positive case because there is direct wrapped-unit evidence for both subsystem-local validation and runtime control mutation.
- `flash_drum` is controller-ready only when `thermal_mode` is configured to the operating regime that makes `flash_temperature_setpoint` or `flash_pressure` meaningful; the mode selector itself remains a manual constant.
- `splitter` is direct-ready at the contract level, but its vector MV still requires an array-capable controller configuration to satisfy the runtime dimensionality check.
