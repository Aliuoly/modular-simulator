## Severity Ranking Method

- Ranking is evidence-driven from Task 2 control-surface extraction, Task 3 runtime-readiness labels, and Task 4 unit-specific coverage labels.
- Highest priority is assigned where runtime control-contract risk is high and test evidence is weak (`not-ready` or `ready-with-adapter` combined with `missing`/`partial` coverage).
- Lower priority is assigned where direct runtime MV surfaces are already `controller-ready` and unit-specific coverage is `strong`.

## Explicit Include/Exclude Rationale

- `conversion_reactor` include rationale: included in Pass 1 despite lacking direct-ready actuator surfaces because it has an explicit control-relevant mode selector (`thermal_mode`) and reaction-driving knobs that materially affect runtime behavior; this combination is a verified control-contract hotspot in Task 2 and a `not-ready` runtime label in Task 3, so deferring would hide a high-risk interface gap.
- `shortcut_distillation` treatment rationale: kept in Pass 1 as `controller-ready` due to dense direct `T.CONTROLLED` surfaces, but severity is elevated above other direct-ready units because Task 4 marks only `partial` coverage for the explicit `reflux_ratio_setpoint` path; remediation priority focuses on filling this concrete test gap, not redesigning the actuator contract.
